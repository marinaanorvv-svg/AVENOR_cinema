# AVENOR — информационная система кинотеатра

Курсовой проект: Python 3.10+, SQLite (`sqlite3`), интерфейс на Tkinter. Внешних библиотек нет.

## Запуск

```
python main.py          # программа (на Linux может понадобиться: sudo apt install python3-tk)
python seed_demo.py     # по желанию, один раз на пустой базе: 18 фильмов с постерами, залы, сеансы, билеты
```

При запуске создаётся файл `cinema.db` и три демо-учётные записи — **по одной на каждую роль**:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `admin123` |
| Кассир | `kassa` | `kassa123` |
| Покупатель | `buyer` | `buyer123` |

На экране входа кнопки «Админ / Кассир / Покупатель» сами подставляют логин и пароль. Если база пустая, программа
предложит загрузить демонстрационные данные (фильмы, залы, сеансы, билеты) — их же можно загрузить командой
`python seed_demo.py`. Для реальной работы выключите демо-режим (`DEMO_MODE = False` в `main.py`) и смените пароли.
Ошибки программы пишутся в `cinema.log`.

## Выбор мест и постеры

- Как купить билет: «Афиша» → нажать на постер (он перевернётся и покажет описание) → «Выбрать сеанс» → выбрать день и время → нажать на кресла → «Купить».
  Страница фильма в три колонки: слева фильм и карточки сеансов, в центре зал, справа клиент, итог и кнопка. Места нарисованы как мягкие кресла (свободные, VIP, занятые, выбранные),
  весь зал помещается в окно; на кнопке «Купить» показана сумма. Купить можно до 10 мест за раз.
- У каждого фильма в день 1–3 сеанса. Кнопка «Купить» всегда видна внизу страницы фильма, даже в маленьком окне.
- Сеанс, который уже начался, купить нельзя; если фильм заканчивается после полуночи, это видно по подписи
  «до 01:10 (29.10)».
- Как добавить фильм (администратор): «Фильмы» → «Добавить фильм» → заполнить форму → на вопрос «Сразу назначить сеансы?»
  ответить «Да». Время и зал программа выберет сама, без пересечений. То же самое: «Сеансы» → «Расставить автоматически».
- Постеры берутся из `posters/`. Без Pillow Tkinter показывает только PNG, поэтому рядом с каждым постером лежат
  готовые `имя@small.png` и `имя@large.png`; с Pillow (`pip install pillow`) можно подключать любые JPG/PNG.
- Если демо-данные уже были загружены раньше, удалите старый `cinema.db` и запустите программу заново.

## Роли и разделы

| Роль | Разделы |
|---|---|
| Администратор | главная панель, афиша (с продажей), билеты (поиск, фильтры, возвраты), фильмы и жанры, залы, сеансы (в т.ч. отмена), отчёты, пользователи |
| Кассир | афиша (продажа билетов клиентам), билеты и возвраты |
| Покупатель | афиша (покупка билетов себе), «Мои билеты» |

Права проверяются внутри сервисов (`actor.require(...)`), поэтому они действуют и без интерфейса;
скрытые пункты меню — только удобство.

## Структура

```
main.py              точка входа
seed_demo.py         демо-данные
database/            только работа с БД: подключение и транзакции, схема, CRUD, SQL отчётов
services/            бизнес-логика: проверки, права, правила (единственный слой, который зовёт GUI)
gui/                 Tkinter: экраны; formatting / navigation / login_guard / palette не зависят от tkinter
gui/theme.py         тема «неон»: шрифты, стили ttk, загрузка картинок
gui/neon.py          свои виджеты: кнопки-«таблетки», поля, светящиеся панели, пункты меню
gui/assets/          картинки интерфейса (PNG): кнопки, иконки, логотип, иллюстрации
demo_posters/        постеры демо-фильмов (JPG + готовые PNG «@small/@large» для компьютеров без Pillow)
posters/             постеры фильмов (создаётся программой: туда копируются постеры при добавлении фильма)
tools/make_assets.py генератор этих картинок (нужен Pillow; для запуска программы он НЕ нужен)
tests/               автотесты (запуск ниже)
```

## Ключевые правила

- **Двойная продажа места невозможна**: транзакция `BEGIN IMMEDIATE` + явная проверка + уникальный индекс в БД.
  Покупка нескольких мест — атомарная (все билеты или ни одного).
- Продажа и возврат закрываются в момент начала сеанса.
- Сеансы в одном зале не пересекаются (перерыв 15 минут, `CLEANING_BREAK_MIN`); сеанс в прошлом создать нельзя.
- На сеанс с проданными билетами нельзя менять время/зал/цену; зал с сеансами нельзя перестроить или удалить.
- Пароли хранятся только как PBKDF2-хеш с солью. Не более 5 неудачных входов подряд — пауза 30 секунд.
- Отчёты по выручке — кассовый метод: продажи в день покупки, возвраты в день возврата. Экспорт в CSV
  (разделитель `;`, UTF-8 с BOM — открывается в русском Excel).
- Постеры в афише: PNG и GIF (Tkinter без Pillow других форматов не показывает).

## Свои картинки

- **Постеры фильмов**: войдите администратором → «Фильмы и жанры» → «Добавить фильм» или «Изменить» → поле «Постер» →
  «Обзор…». Выбранный файл копируется в папку `posters/` рядом с программой, поэтому её нужно переносить вместе с проектом.
  Лучше вертикальная картинка (примерно 2:3). Без дополнительных библиотек показываются PNG и GIF; если установить
  Pillow (`pip install pillow`), работают и JPG/WEBP, а постер сам подгоняется под карточку. Фильмы без постера получают
  красивую заглушку с названием.
- **Оформление** (иллюстрации, иконки, кнопки): файлы в `gui/assets/`. Любой можно заменить своим с тем же именем и
  размером (например, `popcorn.png`, `login_hero.png`, `logo_mark.png`) либо перерисовать скриптом `python tools/make_assets.py`.

## Внешний вид

Цвета и шрифты — `gui/palette.py` и `gui/theme.py`. Картинки (свечение, скругления, иконки) нарисованы заранее
скриптом `python tools/make_assets.py` (Pillow) и лежат в `gui/assets/`. Нужен Tk 8.6 (идёт с Python 3.10+).

## Администратор (доработка)

- **Главная** — карточки (фильмы, действующие сеансы, залы, билеты и выручка за сегодня, пользователи), график выручки за 7 дней,
  ближайшие сеансы, последние продажи. Данные берутся из БД, обновляются при открытии, по кнопке и раз в 30 секунд.
- **Билеты** — все билеты: поиск по номеру и покупателю, фильтры по фильму, статусу, датам сеанса и покупки, подробности, возврат.
- **Фильмы и жанры** — у жанров видно число фильмов; нажатие на жанр показывает его фильмы.
- **Сеансы** — фильтры по датам, фильму и залу; «Отменить сеанс» возвращает все проданные билеты и убирает сеанс из афиши
  (история билетов сохраняется; поле `sessions.is_cancelled`).
- **Отчёты** — выручка, посещаемость, заполняемость залов, самые посещаемые сеансы, продажи по кассирам (поле `tickets.seller_id`);
  быстрый выбор периода; экспорт в CSV. Старые базы дополняются новыми колонками автоматически.
- **Пользователи** — поиск и фильтры, создание кассиров, правка логина и ФИО, роль, блокировка, сброс пароля.

## Кассир (доработка)

Вход: `kassa` / `kassa123` (после «Заполнить демо-данными»). Меню кассира: **Главная · Продажа билетов · Поиск билетов · Возврат билетов · История продаж · Смена**.

- **Смена.** Без открытой смены продажа и возврат недоступны (проверяется в сервисе, внутри транзакции). У кассира не может быть двух открытых смен (частичный уникальный индекс `ux_shifts_one_open` + проверка). При закрытии показывается итоговый отчёт (можно сохранить в .txt).
- **Продажа.** Фильм → дата → сеанс → схема зала → места (несколько) → оплата (наличные со сдачей / карта) → билеты. Доступность мест перепроверяется при оплате; если место успели продать на другой кассе, схема обновляется и выводится предупреждение. Продажа и билеты сохраняются одной транзакцией (таблица `sales`, `tickets.sale_id`).
- **Билет.** AVENOR, номер, фильм, дата, время, зал, ряд, место, цена, дата покупки, код `AVN-000123-9F2A4C`. Кнопка «Печать / PDF» сохраняет HTML и открывает его в браузере (печать или «Сохранить как PDF»). QR-кода нет — только контрольный код.
- **Поиск и возврат.** Поиск по номеру, фильму, дате, номеру сеанса, покупателю, статусу. Возврат: проверка правил, подтверждение, место освобождается, запись о продаже и история сохраняются (`tickets.refunded_by`), повторный возврат запрещён.
- **История.** Кассир видит только свои продажи (фильтр по `cashier_id` в запросе); общих финансовых отчётов нет.
- **Права.** Новое право `USE_CASHIER_DESK` есть только у кассира; админ и покупатель разделы кассы не видят.
- Старые продажи кассиров при первом запуске новой версии группируются в записи `sales` (способ оплаты — «Не указан»).

## Покупатель (доработка)

Вход: `buyer` / `buyer123` (после «Заполнить демо-данными» или кнопкой «Покупатель» на экране входа). Меню покупателя: **Главная · Афиша · Мои билеты · История покупок · Личный кабинет**. На macOS и Linux запускайте `python3 main.py`.

- **Главная.** Логотип, приветствие по имени, ближайший сеанс покупателя, подборки «Сейчас в афише», «Популярное» (по числу реально проданных билетов) и «Новинки» (последние добавленные в афишу фильмы; дат проката в базе нет).
- **Афиша.** Только фильмы с неначавшимися и неотменёнными сеансами; поиск по названию, фильтры по жанру и возрасту, сортировка. Если ничего нет — понятное сообщение.
- **Страница фильма.** Постер, описание, жанр, длительность, возраст, выбор даты и сеанса, интерактивная схема зала (свободно / занято / выбрано / VIP, несколько мест, пересчёт цены). Перед оплатой места проверяются заново; если место занял другой покупатель или кассир, схема обновляется и выводится предупреждение. Схема сама обновляется раз в 15 секунд.
- **Заказ и оплата.** Страница заказа с постером и составом; оплата тестовая картой (проверка номера по алгоритму Луна, срока и CVC; деньги не списываются, данные карты нигде не сохраняются; для проверки подойдёт 4242 4242 4242 4242). Заказ (`orders`) и билеты создаются одной транзакцией, привязаны к учётной записи покупателя; при ошибке не сохраняется ничего.
- **Электронный билет.** AVENOR, номер, фильм, постер, дата, время, зал, ряд, место, цена, дата покупки, код проверки `AVN-000123-9F2A4C`. «Печать / PDF» сохраняет HTML со вшитым постером и открывает его в браузере (печать или «Сохранить как PDF»). QR-кода нет — только код проверки.
- **Мои билеты.** Только собственные билеты карточками: предстоящие / прошедшие / возвращённые; просмотр билета и возврат (подтверждение, правила те же, что на кассе: до начала сеанса, один раз). Запись о покупке остаётся, место освобождается и сразу доступно кассе.
- **История покупок.** Только свои заказы: поиск по номеру, период, статус (оформлен / частично возвращён / возвращён), состав заказа и билеты.
- **Личный кабинет.** Имя, телефон, email, логин, дата регистрации; изменение данных с проверкой (чужие телефон и email занять нельзя), смена пароля (хранится только хеш), переходы к билетам и заказам, выход.
- **Права.** Новые права `USE_PORTAL` и `REFUND_OWN_TICKET` есть только у покупателя и проверяются в сервисах (`buyer_service`, `ticket_service`). Чужие билеты и заказы недоступны (PermissionDenied).
- **База.** Новая таблица `orders`, поле `tickets.order_id`, `users.created_at` (у старых учётных записей дата неизвестна). При первом запуске новой версии прежние покупки покупателей собираются в заказы (оплата — «Не указан»).

## Финальная проверка и интеграция ролей

Все три роли работают на **одной** базе `cinema.db` (папка проекта); отдельных копий данных у ролей нет.

- **Запуск:** `python3 main.py` (Python 3.10+ с tkinter; сторонних пакетов нет, Pillow — по желанию, для постеров).
- **Ваши данные.** Файл `cinema.db` в архив не входит. Чтобы сохранить имеющиеся данные, скопируйте свой `cinema.db` (и папку `posters/`, если есть) в папку проекта *до* первого запуска. Старая база обновляется автоматически и без потери данных (добавляются недостающие колонки и таблицы `shifts`, `sales`, `orders`); проверено на базах первоначальной версии и этапа администратора. Новая пустая база создаётся только если файла нет.
- **Перед обновлением** сделайте копию `cinema.db` — на всякий случай.
- **Тесты:** `python3 -m unittest discover -s tests -t .` — все работают на временных базах, ваши данные не затрагивают. Сквозные сценарии трёх ролей — `tests/test_integration.py` (витрина → покупка → касса → возврат → отчёты, двойная продажа в параллельных потоках, права при прямых вызовах сервисов, аудит БД).
- **Сообщение «Произошла непредвиденная ошибка».** Теперь в окне показаны тип и текст ошибки, а полный Traceback пишется в `cinema.log` рядом с `main.py`.
- **Ограничения.** Самостоятельной регистрации покупателя на экране входа нет: учётные записи создаёт администратор («Пользователи»). Оплата — тестовая; QR-кода нет.
- **Даты в афише покупателя.** Над карточками — кнопки «Все даты · Сегодня · Завтра · 18.11 вт …» (только дни, когда есть сеансы). На афише выбор дня фильтрует фильмы; на главной кнопка открывает афишу сразу на этот день. На карточке указан ближайший сеанс («Завтра, 18:00»). Карточки стали компактнее, на главной каждая подборка — один ряд (остальное — в «Вся афиша»).

## Изменения аудита

- Ошибка `'PhotoImage' object has no attribute 'subsample'` (при установленном Pillow): миниатюры постеров строит `neon.poster_thumb`.
- Правило возврата одно для всех ролей: `ticket_service.refund_block_reason`; экраны показывают причину отказа.
- Экран возврата кассира учитывает открытую смену.
- Интерфейс спокойнее: приглушённый фон-«звёзды», панели без свечения, шрифты мельче 10 pt убраны.
- Тесты: `python -m unittest discover -s tests` (354 теста; GUI-тесты идут на заглушке tkinter).
